**使用者描述對目前已重播的 DD_SWITCH 成交流程是正確的：P3 當期狀態在收盤後作為切換訊號，下一交易日才執行。不能僅因控制含當期虛擬收益，就把它判定為偷看下一天。**

## 實測確認

以實際原來源链輸入，在9/29、9/30、10/1、10/5四個切點：

1. 把母帳截斷至T日，P3狀態與DD控制前綴均和完整資料一致。
2. 將T日以後母NAV分別放大10倍／縮成0.1倍，T日以前的P3／DD判斷與premium42均不變。
3. 單獨修改P3母NAV的T日數值，premium42(T)不變，確認TRAIL42確實排除當日報酬。
4. 31筆種子後Path3訂單均標示AFTER_CLOSE及NEXT_SESSION_OPEN；39筆種子後成交均晚於訊號日。前次完整T+1稽核已確認全部在下一交易日、0筆同日成交。

`prefix_checks.csv`／`p3_order_clocks.csv`與`summary.json`保存實測結果及來源hash。

## 原研究裡另一個「當日收益」含義

Soft-core `simulate_fill` 會先以T日book／權重更新虛擬配置，再計算T日close-to-close收益。控制實驗只改最後一天的book，其他99日不動：COMP最後NAV=1.1、SAT=0.9，確認它確實是當期狀態對當期收益的虛擬評分。

這樣的虛擬分數可以在T日收盤後算出，作為T+1策略特徵；但其收益不能直接當作當日已成交的獲利。原研究DD收益線也將T日DD選擇套到T日報酬，故原長期研究績效仍需成交重建。這與「下一日切換能否使用這個當期指標」是兩個不同的稽核項目。

因此，先前「因母帳含T+0就要將控制全部改T+1」的說法過度概括。**應保留當期收盤指標→下一日成交設計，核對各輸入在當時是否已可得；不應不分層次將所有訊號再lag一次。**

## 證據邊界

本次確認的是程式在給定日線／母帳上的時間依賴和已重播的成交資格。截斷／未來擾動沒有證明歷史股利公告、資料修訂及輸入vintage在當時已公布，也沒有驗證盤中價格、T+0真實成交或委託簿容量。8.5842%仍稱為原來源鏈控制下的短視窗T+1紙上成交績效；不把虛擬母帳長期收益當成可成交聲明。
